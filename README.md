# Meshtastic HOBO Field-Node Firmware

> **Canonical production branch:** `hobo-mx2001-mx2201-mx2203`
>
> **Purpose:** HOBO field nodes only. Heltec gateway development belongs on `cca-heltec-sensor-gateway`.
>
> **Supported field radios:** Seeed XIAO nRF52840 + Wio-SX1262 and RAK4631 / RAK19003.
>
> **Supported HOBOs:** MX2001, MX2201, MX2203.

This repository is a custom Meshtastic firmware tree for remotely reading Onset HOBO loggers over Bluetooth and moving those measurements across a Meshtastic mesh.

## Production HOBO behavior

The same universal firmware supports:

| HOBO | Automatic data | Direct `READ` |
|---|---|---|
| MX2001 | Water level + temperature | Water level + temperature |
| MX2201 | Temperature | Temperature |
| MX2203 | Temperature | Temperature |

### Automatic telemetry follows the logger itself

Automatic packets are **not** generated by a free-running radio timer.

The firmware reads the HOBO `STATUS` response, learns the logger's configured logging interval and current write pointer, then waits for the write pointer to advance. A confirmed new HOBO record triggers:

1. a fresh `NEWREAD64` read;
2. exactly one Meshtastic transmission;
3. write-pointer consumption only after the packet is successfully queued.

A manual `READ` does not consume the automatic pointer or reset the automatic schedule. If `STATUS` tracking fails, automatic telemetry pauses rather than inventing a schedule.

Final RAK4631 validation with an MX2201 at a 20-second logger interval produced consecutive automatic packet cadences of approximately **19.85 s** and **19.88 s**, with the packet queued about **0.2 s** after the new logger record was detected.

## Direct-message commands

Send these as a direct Meshtastic text message to the field radio. A leading slash is optional and command matching is case-insensitive.

| Command | Function |
|---|---|
| `LOGGER` | Show connected HOBO model, MAC, BLE RSSI, logging interval, and lock state |
| `READ` | Perform an immediate fresh read without disturbing automatic telemetry |
| `LOCK` | Persist the currently identified HOBO BLE MAC and reconnect only to that logger |
| `UNLOCK` | Clear the saved logger assignment and resume discovery |

### Field installation sequence

1. Flash the correct field-node build.
2. Power it with the intended HOBO nearby.
3. DM `LOGGER` and verify the model/MAC/interval.
4. DM `READ` and compare the value with the logger.
5. DM `LOCK` at the final monitoring site.
6. Reboot and verify `LOGGER` still reports the locked target.

## Repository rules

1. Treat `hobo-mx2001-mx2201-mx2203` as the universal HOBO field-node source of truth.
2. Do not create a separate production branch solely because the radio is RAK versus Seeed; both targets belong to the universal implementation unless a temporary hardware-debug branch is needed.
3. Keep `LOGGER`, `READ`, `LOCK`, and `UNLOCK` intact on production field-node builds.
4. Keep automatic telemetry tied to confirmed HOBO write-pointer advancement.
5. Do not replace pointer-gated automatic telemetry with blind periodic transmission.
6. Keep Heltec gateway work off this branch; use `cca-heltec-sensor-gateway`.
7. Keep experimental water/PIR/trail work isolated until it is intentionally validated and promoted.
8. Preserve known-good firmware states with immutable tags rather than long-lived obsolete deployment branches.

The full Meshtastic source tree remains in this repository because the normal Meshtastic `src/`, `variants/`, libraries, build configuration, and platform code are required to compile these custom targets.
